④ 프로토콜 버전 확인 포함지금부터 서버와 APK가 따로 업데이트되니 구버전 APK에 "업데이트하세요" 안내
⑤ 운영 — Claude가 브라우저 제어사용자는 로그인·2단계 인증·결제·구매 확정만

코드 수정 (작게, 테스트 먼저)

⚠ 발견한 버그 — M2b를 막음. ServerAddress가 포트 생략 시 스킴과 상관없이 7777을 붙여서, wss://play.도메인이 wss://play.도메인:7777/ws가 됩니다. Caddy(443)에 닿지 못합니다.

1. ServerAddress 포트 수정

ws + 포트 생략 → 7777(지금과 같음, 같은 Wi-Fi 개발용) · wss + 포트 생략 → 443 · 명시 포트는 그대로.

2. 서버 --host 옵션

기본 0.0.0.0(PC 테스트 방식 그대로). 클라우드에선 127.0.0.1로 Caddy를 거친 접속만 받음.

3. 프로토콜 버전 확인

  • 클라이언트가 /ws?v=1로 접속합니다. WebSocketClientTransport.ConnectAsync 한 곳에서 붙이므로 호출부 변경은 없습니다.
  • 서버는 좌석을 주기 전에 버전을 확인합니다. 다르거나 없으면 SessionFaulted("앱을 업데이트해 주세요")를 보내고 닫습니다. 좌석·대기실은 건드리지 않습니다.
  • 클라이언트는 이미 있는 "폴트 문구 → 메뉴 복귀" 경로를 그대로 탑니다. 새 UI는 0개입니다. 지금 폰에 깔린 구 APK도 이 안내를 받습니다.

이번에 안 하는 것: 접속 화면에 주소 미리 채우기(M4) · 헬스체크·모니터링 · 다중 서버 · 무중단 배포(M5) · 모르는 사람의 좌석 점유 방지(M3 방·초대 코드).

역할 분담

  • AWS 로그인 · 2단계 인증
  • 결제 정보 입력 · 구매 확정 클릭 (Claude는 결제 화면에서 멈추고 금액을 보여줌)
  • 비용이 드는 단계마다 "진행"
Claude — 브라우저 제어 + 스크립트

  • SSH 키 → C:\Users\user\.keys\ (저장소에 절대 안 넣음)
  • 서버 초기 세팅 스크립트 · deploy-server.ps1 · 운영 안내서
  • 단계마다 스크린샷 + nslookup/curl로 검증

완료 기준 (전부 통과해야 M2b 완료)

#기준확인 방법
1S23이 모바일 데이터로 접속해 매치 완주실기 + 서버 로그
2인증서 정상curl -v 체인 검증
3프로세스가 죽으면 다시 뜸강제 종료 → 재기동 → 접속
4VM 재부팅 후 다시 뜸재부팅 → 자동 시작 → 접속
5외부 7777 직접 접속 불가외부에서 접속 시도 실패
6버전 불일치 시 업데이트 안내테스트 클라이언트 + 지금 폰에 깔린 구 APK
7배포 스크립트 한 번으로 갱신사소한 변경 → 배포 → 접속
8밀린 실기 확인 3건동시 결정 · 스몰 티츄 즉시 · 캔버스 누적
9자동 테스트 그린dotnet 전체 · Unity Presentation · 미러 무드리프트

위험과 대응

위험대응
Android wss 인증서Unity TLS가 Let's Encrypt를 받아들이는지는 실기에서만 확인됩니다. 에디터 → S23 순으로 확인하고, 막히면 원인을 조사합니다(추측 수정 금지).
배포 = 판 끊김판이 없을 때만 배포합니다. 스크립트가 실행 전에 확인을 묻습니다.
CPU 크레딧M2b는 동시 매치가 1개라 문제없습니다. 용량 측정은 M3에서 합니다.
키·서버 분실서버에 보관할 상태가 없어서 세팅 스크립트로 다시 만들 수 있습니다. 키는 업로드 키와 같은 폴더에 두고 함께 백업합니다.
도메인 만료자동 갱신을 켭니다. 만료되면 출시 앱 전체가 접속 불가가 됩니다.

작업 순서

  1. 코드 수정 3개(TDD, 음성 대조) → dotnet + Unity 그린
  2. AWS: 인스턴스 · 고정 IP · 방화벽 · 도메인 · DNS (브라우저 제어)
  3. 서버 초기 세팅 → 첫 배포 → 완료 기준 2~5
  4. 에디터 접속 → APK 빌드 → S23 LTE 실기 → 완료 기준 1 · 6 · 7 · 8

비용: 인스턴스 월 약 $7 + 도메인 연 $13~15 정도. 실제 금액은 실행할 때 화면에서 확인합니다.
