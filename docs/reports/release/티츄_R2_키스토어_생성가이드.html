R2 Task 2 — 업로드 키스토어 생성

Tichu Master · Google Play 출시 · 이 단계는 비밀번호를 다루므로 사용자가 직접 실행합니다
0 / 10
준비는 끝나 있습니다. Task 1에서 *.jks·*.keystore·*.p12·keystore.properties가 이미 git에서 차단됐습니다(커밋 cca4b8a, 4개 패턴 실동작 확인 완료). 그래서 지금 키를 만들어도 실수로 커밋될 수 없습니다.

설치할 것도 없습니다. keytool은 Unity 번들 JDK(Temurin 17.0.18)에 들어 있습니다.
이 페이지는 안내만 합니다. 키는 사용자 PC의 keytool이 만듭니다 — 웹에서 키를 생성하거나 비밀번호를 입력받는 순간 그 자체가 유출 경로가 됩니다. 비밀번호를 이 페이지나 대화창에 입력하지 마세요.

먼저 알아둘 것 — 비밀번호는 하나입니다

번들 JDK가 17이라 keytool의 기본 키스토어 형식이 PKCS12입니다. 이 형식은 저장소 비밀번호와 키 비밀번호가 같아야만 하고, 그래서 keytool이 두 번째 비밀번호를 아예 묻지 않습니다.

계획서에는 "같게 두어도 무방"으로 적었지만, 실제로는 "같을 수밖에 없음"입니다. 나중에 환경변수 TICHU_KEYSTORE_PASS와 TICHU_KEY_PASS에 같은 값을 넣게 되는 이유가 이것입니다.

단계

1

키 디렉터리 만들기

저장소 바깥에 둡니다. 프로젝트 폴더 안에 두면 언젠가 실수로 딸려 들어갑니다.

New-Item -ItemType Directory -Force "$env:USERPROFILE\.keys"
2

업로드 키 생성

& "E:\6000.3.17f1\Editor\Data\PlaybackEngines\AndroidPlayer\OpenJDK\bin\keytool.exe" -genkeypair -v -keystore "$env:USERPROFILE\.keys\tichumaster-upload.jks" -alias tichumaster -keyalg RSA -keysize 2048 -validity 10000

별칭은 반드시 tichumaster — 나중에 등록할 환경변수와 일치해야 빌드가 서명됩니다. -validity 10000은 약 27년으로, Play가 요구하는 2033-10-22 이후 만료 조건을 넉넉히 넘깁니다.

keytool이 순서대로 물어보는 것 (한국어로 표시됩니다)
키 저장소 비밀번호 입력이게 유일한 비밀번호입니다. 6자 이상. 잊으면 재설정 절차를 밟아야 하니 비밀번호 관리자에 바로 저장하세요.
새 비밀번호 다시 입력확인용.
이름과 성을 입력하십시오본명이 아니어도 됩니다. Tichu Master 정도로 충분합니다.
조직 단위 / 조직 이름kas328 또는 비워도 됩니다(Enter).
구/군/시 / 시/도 이름비워도 됩니다(Enter).
2자 국가 코드KR
...이(가) 맞습니까?y 입력 후 Enter.

이 정보는 앱 스토어 표시에 쓰이지 않습니다. 서명 인증서의 식별 정보일 뿐이라 편하게 채우셔도 됩니다. 다만 한 번 정하면 이 앱의 서명 인증서에 영구히 박힙니다.

3

생성 확인

& "E:\6000.3.17f1\Editor\Data\PlaybackEngines\AndroidPlayer\OpenJDK\bin\keytool.exe" -list -keystore "$env:USERPROFILE\.keys\tichumaster-upload.jks"

기대 출력: tichumaster, <날짜>, PrivateKeyEntry, 와 SHA-256 지문 한 줄.

4

백업 — 3요건을 모두 만족해야 합니다

업로드 키를 잃어도 Play App Signing 덕분에 재설정 요청으로 복구는 가능합니다(승인 1~2 영업일). 영구 손실은 아닙니다. 다만 재설정은 시간과 번거로움을 물리는 일이라, 백업을 안 할 이유는 없습니다.
  • 물리적으로 다른 2곳 — 개발 PC가 사라져도 살아남아야 하므로 최소 한 곳은 PC 외부(USB·외장하드·클라우드).
  • 비밀번호는 키 파일과 분리 보관 — 같은 폴더에 메모로 두면 백업이 아니라 단일 실패점이 하나 더 생기는 것입니다.
  • 파일명에 날짜 — tichumaster-upload-2026-08-19.jks
5

복원 테스트 — 백업본으로 실제 서명이 되는지

열어보지 않은 백업은 백업이 아닙니다. 백업본을 되가져와 진짜로 서명이 되는지 확인합니다. 아래 <백업본 경로>만 실제 위치로 바꾸세요.

$AP = "E:\6000.3.17f1\Editor\Data\PlaybackEngines\AndroidPlayer"
$tmp = "$env:TEMP\r2-restore-test"
New-Item -ItemType Directory -Force $tmp | Out-Null
Copy-Item "<백업본 경로>\tichumaster-upload-2026-08-19.jks" "$tmp\restored.jks"
"restore test" | Out-File "$tmp\payload.txt"
Compress-Archive -Path "$tmp\payload.txt" -DestinationPath "$tmp\dummy.zip" -Force
& "$AP\OpenJDK\bin\jarsigner.exe" -keystore "$tmp\restored.jks" "$tmp\dummy.zip" tichumaster
& "$AP\OpenJDK\bin\jarsigner.exe" -verify "$tmp\dummy.zip"

마지막 줄이 jar verified. 를 출력하면 통과입니다. 서명할 때 비밀번호를 한 번 물어봅니다.

6

임시 파일 정리

Remove-Item -Recurse -Force "$env:TEMP\r2-restore-test"
7

환경변수 4개 등록

사용자 범위로 등록하면 이후 실행되는 프로세스(Unity 포함)가 값을 상속합니다. 덕분에 빌드할 때마다 비밀번호를 다시 입력할 필요도, 대화창에 노출할 일도 없습니다. TICHU_KEYSTORE_PASS와 TICHU_KEY_PASS에는 같은 값을 넣습니다(PKCS12라 비밀번호가 하나입니다).

[Environment]::SetEnvironmentVariable('TICHU_KEYSTORE_PATH', "$env:USERPROFILE\.keys\tichumaster-upload.jks", 'User')
[Environment]::SetEnvironmentVariable('TICHU_KEY_ALIAS', 'tichumaster', 'User')
[Environment]::SetEnvironmentVariable('TICHU_KEYSTORE_PASS', '여기에_비밀번호', 'User')
[Environment]::SetEnvironmentVariable('TICHU_KEY_PASS', '여기에_같은_비밀번호', 'User')
트레이드오프를 알고 쓰세요. 사용자 범위 환경변수는 레지스트리에 평문으로 저장됩니다. 1인 개발 PC에서는 통상 수용하는 수준이지만, 이 PC를 다른 사람과 공유한다면 대신 빌드 직전에 $env:TICHU_KEYSTORE_PASS = '...' 처럼 세션 변수로만 설정하고 그 창에서 빌드를 실행하세요.
8

등록 확인 — 값은 출력하지 않습니다

새 PowerShell 창을 연 뒤 실행하세요. 이미 열려 있던 창은 갱신된 값을 상속하지 않습니다.

'TICHU_KEYSTORE_PATH','TICHU_KEYSTORE_PASS','TICHU_KEY_ALIAS','TICHU_KEY_PASS' | ForEach-Object { "{0} = {1}" -f $_, $(if ([Environment]::GetEnvironmentVariable($_,'User')) { 'OK' } else { '미설정' }) }

4줄 모두 OK여야 합니다. 값 자체는 찍지 않으므로 화면 공유 중에도 안전합니다.

9

Unity 종료

다음 단계(Task 4)는 배치 모드로 릴리스 AAB를 빌드하는데, Unity 에디터가 프로젝트를 잠그고 있으면 실패합니다. 또 ProjectSettings.asset을 디스크에서 편집해야 해서 에디터가 떠 있으면 덮어써집니다.

절대 하지 말 것

  • 비밀번호를 대화창·이 페이지·커밋 메시지에 쓰지 않기. 환경변수로만 두면 됩니다.
  • 키 파일을 프로젝트 폴더 안에 두지 않기. 차단 규칙이 있어도 습관이 사고를 만듭니다.
  • 별칭을 tichumaster 말고 다른 걸로 만들지 않기. 환경변수와 어긋나면 서명이 실패합니다.
  • 백업 없이 다음 단계로 넘어가지 않기. 지금이 가장 싸게 백업할 수 있는 시점입니다.

다 끝나면

대화창에 "Task 2 완료"라고만 알려주세요. 비밀번호는 알려주지 않으셔도 됩니다 — 환경변수에서 알아서 읽힙니다.

이어서 제가 Task 4를 진행합니다: 릴리스 AAB 빌드 → bundletool로 targetSdk 36·versionCode 실측 → jarsigner로 서명 검증 → 키 경로가 저장소에 새지 않았는지 확인 → 커밋. IL2CPP 릴리스 빌드라 수십 분 걸릴 수 있어 백그라운드로 돌립니다.
