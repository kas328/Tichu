게임은 완성됐고, 남은 건 전부 "출시 실무"입니다. Phase 0(룰 엔진) · Phase 1(MVP) · Phase 2(PIMC AI)가 모두 main에 머지·푸시됐고, 2026-08-08 R1 출시검증에서 DoD 4게이트 전부 Pass로 Phase 1이 공식 종료됐습니다. 다음 관문은 R2 빌드/서명이고, 그 첫 항목인 keystore 생성·백업이 프로젝트 전체에서 가장 되돌릴 수 없는 작업입니다.

1. 지금까지 — 무엇을 만들었나

Phase 0 — 룰 엔진

순수 C# 코어. 조합 인식 · 상태기계 · 정산. 155 테스트 + 10만판 시뮬레이션 무결성 검증. 이 코어가 이후 모든 AI 벤치의 오라클 역할을 합니다.

Phase 1 — MVP (종료)

헤드리스 게임플로 → 프레젠테이션 → 앱셸(VContainer DI + R3 AppFlowMachine) → 비주얼/손맛(카드뷰·풀링·DoTween·폭탄 글로우) → 사운드(SFX·BGM·볼륨) → 빌드/60fps 게이트. 진실(Core)과 연출(Presentation) 분리를 끝까지 유지.

Phase 2 — AI (PIMC)

완전정보 다세계 몬테카를로 탐색. 4난이도 티어(쉬움/보통/어려움/전문가) + 난이도 선택 UI. 최대 성과는 학습 콜 헤드: 그랜드 티츄 +4.97/R, 스몰 티츄 +2.91/R (둘 다 통계적 유의) — 실기 플레이에서도 체감 확인됨.

R1 — 출시검증 (2026-08-08 종결)

S23 실기 1패스. 좋음 20 · 이상함 4 → 발견 4건 전부 처분(봉황 낭비 버그 수정 · 세이프에어리어 4차 수정 · 리드순서는 "AI가 옳음"으로 기각 · 티츄 응징은 천장 수용). DoD 4게이트(완주·성능·부채검증·손맛) 전부 Pass.

이 프로젝트가 얻은 방법론 자산

  • 격리 미러드 벤치가 강도 주장의 유일한 근거 — 인간 직관으로 "낭비수"처럼 보이는 AI 수의 상당수가 실제로는 near-optimal. 리드/셰딩 계열 오버라이드는 4~5회 연속 회귀를 냈고, 성공 사례는 엔드게임 셰딩(+34.3/R) 하나뿐.
  • 채택 기준 3단 — ①강도 유의 개선(벤치 CI) ②강도 중립이나 관측 교정(회귀 없음) ③회귀 → 파킹(코드 보존·플래그 OFF). 파킹된 레버가 여럿 남아 있어 되살릴 수 있습니다.
  • 페어드 벤치가 정확 — 미러드 벤치의 per-round CI는 과대추정됨(콜 헤드 작업에서 교훈).

4. R2 상세 계획 (제안)

R2-1 keystore가 프로젝트 전체에서 가장 되돌릴 수 없는 작업입니다. Play에 한 번 업로드하면 그 서명 키로만 갱신할 수 있고, 분실하면 같은 앱을 영원히 업데이트할 수 없습니다(새 패키지명으로 재출시 = 리뷰·설치수 전부 소멸). Play App Signing에 등록하면 구글이 배포 키를 보관해 주지만, 업로드 키는 여전히 내 책임입니다. 생성 즉시 오프라인 2곳 + 비밀번호 별도 보관을 권합니다.
태스크내용검증(게이트)
R2-1
최우선		 업로드 keystore 생성 + 백업 절차 확립. 비밀번호/별칭 기록, 저장소에 커밋 금지(.gitignore 확인). 다른 경로의 백업본으로 실제 서명이 되는지 복원 테스트까지
R2-2 AndroidTargetSdkVersion = 36 명시 고정(Automatic 금지 — 빌드 재현성). 번들 SDK에 android-36이 이미 있어 추가 설치 불필요. 빌드 산출물 매니페스트에 targetSdkVersion 36 확인
R2-3 출시 버전 확정: bundleVersion 1.0.0, versionCode 정책 결정(Play는 동일 versionCode 재업로드 불가). 내부 테스트 업로드가 거부되지 않음
R2-4 AAB 릴리스 빌드(Play 신규 앱은 AAB 필수) + R8/minify + IL2CPP 릴리스 구성. AAB 생성 성공 · 용량 기록
R2-5 릴리스 빌드 S23 실기 스모크: 개발 빌드가 아니므로 FpsOverlay 미표시 확인, 풀 매치 완주, 크래시 0. 한 판 완주 + 크래시 0 + 코너 UI 정상(E5 회귀 없음)

R2에서 터질 수 있는 것 — 미리 확인할 3가지

스트리핑 · R8 회귀

개발 빌드는 통과했지만 릴리스는 처음입니다. VContainer(DI)·R3가 리플렉션을 쓰므로 코드 스트리핑에서 타입이 날아가면 런타임에만 터집니다. link.xml 필요 여부를 실기 스모크로 판정.

16KB 페이지 크기

최근 Play 제출 요건에 네이티브 라이브러리 16KB 정렬이 포함됩니다. Unity 6.3은 기본 대응으로 알고 있으나 추정으로 넘기지 않고 빌드 산출물에서 확인할 항목.

API 36 edge-to-edge

targetSdk를 올리면 시스템 바 뒤까지 그려집니다. R1에서 세이프에어리어를 4차까지 수정해 대비돼 있지만(androidRenderOutsideSafeArea: 1), targetSdk 변경 후 재확인이 필요한 바로 그 영역입니다.

일정 사실(웹 확인): 2026-08-31부터 Google Play 신규 앱·업데이트는 API 36(Android 16) 이상 타겟이 필수입니다(오늘 기준 12일 후). 다만 우리는 처음부터 36으로 고정할 것이므로 이 날짜에 쫓길 이유는 없습니다 — 오히려 35로 타협할 이유가 사라진 것에 가깝습니다.

5. 병행 트랙 — 카드 아트

S23 실기에서 카드 무늬 기호가 안 보이는 문제가 발견됐습니다(원인: ♠♣♥♦ 글리프가 Android 폰트 폴백에 없음 + 티츄 4무늬를 포커식 2색으로 뭉갬). 출시 차단 사항은 아니지만 — 무늬는 스트레이트 플러시 폭탄 판독에만 쓰이고 이미 빨강 테두리로 표시됨 — 스토어 스크린샷(R3)의 품질에 직결됩니다.

  • 이음새는 이미 있음 — CardSpriteAtlas가 아트 도입용으로 설계돼 있어 코드 0줄로 스프라이트만 꽂으면 됩니다.
  • 유일한 비확정 작업 — 티츄는 56장(포커 52 + 특수 4: 마작·개·봉황·용). 특수 4장은 어떤 포커 팩에도 없어 제작 필요.
  • 제약 — Kenney CC0 권장. 공식 티츄 덱 아트 사용 금지(Fata Morgana/Abacusspiele 활성 IP).

순서 판단: R3 스크린샷을 찍은 뒤에 아트가 들어오면 스크린샷을 다시 찍어야 합니다. 따라서 R2와 병행하되 R3 이전에 끝내는 배치가 낭비가 없습니다.
