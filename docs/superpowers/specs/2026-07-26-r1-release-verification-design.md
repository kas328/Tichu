# R1 — 출시 검증 (Release Verification) 설계

- 날짜: 2026-07-26
- 상위 목표: **Google Play 정식 출시** (5트랙 로드맵 R1~R5 중 첫 관문)
- 이 스펙의 범위: **R1 검증** — D6 실기기 성능 게이트 + 미확인 AI 부채 통합 플레이테스트 → Phase 1 공식 종료
- 선행/후행: R1 통과가 R2(빌드/서명)~R5(배포)의 관문. R1의 저사양 성능 판정은 R5(내부 테스트 트랙)와 약한 의존.

---

## 1. 배경 & 문제

게임은 **기능적으로 완성**됐다. Phase 0(룰엔진, 155 tests + 10만판 무결성), Phase 1(MVP·비주얼·D5.1 사운드), Phase 2(AI = PIMC, 난이도 티어·콜헤드·다수 강도 레버)까지 `main`에 머지·푸시됨(main = origin/main 동기).

그러나 두 가지가 **검증되지 않은 채** 남아 있다.

1. **Phase 1이 공식적으로 닫힌 적이 없다.** D6 게이트(실기기 60fps + "한 판 더" 손맛)는 사람만 할 수 있는데 미실행. 코드는 Phase 2까지 앞서갔지만 Phase 1 DoD는 미종결.
2. **벤치로 채택했지만 실기 미확인인 AI 변경이 누적**됐다. 강도 레버 다수가 "격리벤치 통과 → 채택"만 됐고 실제 플레이에서 육안 확인이 안 됐다.

Play 정식 출시를 목표로 잡은 이상, 검증되지 않은 빌드에 스토어 자산·서명·정책을 붙이는 건 무의미하다. **R1이 전부의 관문**이다.

## 2. 목표 & 성공 기준

R1이 끝나면:

- S23에서 Dev Build APK가 크래시 없이 풀매치를 완주하고, FpsOverlay로 60fps 유지·명백한 병목 없음이 확인된다.
- 미확인 AI 부채 항목이 통합 체크리스트로 전수 관찰되고, 발견된 문제가 분류·처리(또는 명시적 수용)된다.
- Phase 1 DoD가 (S23 현실을 반영한 재정의 기준으로) 판정되어 **Phase 1이 공식 종료**되고 R2 착수 조건이 선다.

## 3. 범위

**포함(R1):**
- R1-a: S23 성능 스모크 게이트 (Dev Build APK + FpsOverlay)
- R1-b: 미확인 AI 부채 통합 체크리스트 1패스 + 발견 분류·처리
- R1-c: Phase 1 공식 종료(대시보드·메모리 갱신, DoD 재판정)

**제외(다른 트랙/병행):**
- 저사양 실기 성능 실측 → R5(Play 사전 출시 보고서). R1은 S23 스모크까지만.
- Release keystore·AAB·타겟 API·R8 → R2.
- 아이콘·스크린샷·스토어 문구 → R3.
- 개인정보처리방침·Data safety·콘텐츠 등급 → R4.
- **IP/상표(브랜딩) 결정** → R1과 무관(코드 검증은 이름과 독립). 단, 출시 전 반드시 해소해야 할 병행 결정으로 §8에 기록.

## 4. R1-a — 성능 게이트 (S23 현실 반영)

### 4.1 DoD#2 재정의 (제품 결정: 저사양 미대응)
**제품 결정**으로 저사양 기기 대응은 범위에서 제외한다 — 저사양 사용자 비중이 미미. 성능 게이트를 현대 중급+ 기기 기준으로 단순화하고, 보유한 **S23 스모크가 그 게이트**다.

| 항목 | 언제 | 판정 방법 |
|---|---|---|
| **DoD#2 — 60fps 스모크(현대 기기)** | R1 | S23 Dev Build + FpsOverlay 상시 녹색(≥55), 적색 스파이크 0 |
| ~~저사양 60fps 확정~~ | — | **범위 제외.** R5의 Play 사전 출시 보고서는 무료 크래시/성능 **참고자료로만** 활용(게이트 아님). |

최소 사양: 현재 minSdk 26(Android 8.0) 유지. 필요 시 R2에서 상향(구형 배제 명시) 검토. R1은 S23에서 "명백한 병목 없음 + 60fps 유지"까지 확인하면 성능 게이트 통과.

### 4.2 절차
1. Unity Hub에 **Android Build Support(SDK·NDK·JDK)** 설치 확인. (D6 시점 미설치 가능성 있음 — 첫 관문.)
2. Build Settings → Platform = Android로 Switch (첫 전환은 에셋 reimport로 수 분).
3. **Development Build** 체크 → Build And Run (S23 USB 연결).
4. FpsOverlay 관찰하며 딜링·교환·플레이 전 구간 60fps 확인.

### 4.3 통과 기준 (R1-a)
- [ ] 풀매치(목표 점수까지) 크래시 0으로 완주.
- [ ] 전 구간 FpsOverlay 녹색(≥55) 유지, 적색 스파이크 없음.
- [ ] DoTween 애니(플레이 팝·차례 펄스·결과 팝) 시 프레임 드랍 체감 없음.
- [ ] 입력(손패 선택·버튼) → 화면 반응 지연 체감 없음.
- [ ] 여러 라운드 연속 시 GC 스파이크 끊김 없음(D3 풀링 효과).

## 5. R1-b — 미확인 AI 부채 통합 체크리스트 (핵심 작업량)

### 5.1 방식
채택했지만 실기 미확인인 변경을 **하나의 가이드 체크리스트**로 통합해, **S23 Expert 난이도 집중 플레이테스트 1패스**로 전수 관찰한다. 각 항목은 "무엇을·어떤 상황에서 볼까"로 기술한다. 기존 인터랙티브 플레이테스트 대시보드(localStorage 체크·결과복사)를 이 항목 세트로 확장한다.

### 5.2 검증 대상 (미확인 부채)

| 항목 | 관찰 포인트 (라이브에서 무엇을 보나) | 근거/상태 |
|---|---|---|
| ③′ 확실승자 리드 | `{10,A}` 유형 손패에서 **A를 먼저** 리드하고 나가는가(10 먼저 리드해 밟히지 않는가) | 라이브 배선 완료·약우월, 미러드 PimcBench 비정보 → 플레이테스트가 최종검증 |
| ① 봉황콤보 보존 | 봉황을 싱글로 헛쓰지 않고 자연 승수로 밟는가 | 강도 −0.5 wash·관측교정, 사용자 "유지" 결정, 실기 미확인 |
| #4 라지티츄 지원 | 파트너가 티츄 콜 시 AI가 최고카드 교환·파트너 밟기 금지·먼저 나가기 금지로 협조하는가 | Cluster A 채택, 공유행동이라 미러드벤치 격리불가 → 플레이테스트가 검증 |
| #4c 살리기 | 콜한 파트너가 못 나갈 상황이면 AI가 살려주는 탈출을 하는가 | 정제 채택, 실기 미확인 |
| C1 교환핀 | (간접) 교환 후 AI가 넘긴 카드 좌석을 정확히 아는 듯한 플레이 | 정확도 수정, 강도 미입증, 실기 미확인 |
| 07-15 배치·D3 구조보존리드 | 스트레이트/트리플/연속페어를 깨는 싱글 리드를 회피하는가 | +0.5 wash 채택, 실기 미확인 |
| ✅ 콜헤드(Grand/Small) | (재확인만) Grand 더 자주·이상한 Small 감소 | 07-24 체감 확정 — 회귀 없는지만 스모크 |

### 5.3 일반 스모크 (부채와 별개, 출시 품질)
- [ ] 4난이도(쉬움/보통/어려움/전문가) 각각 시작·정상 동작.
- [ ] 풀매치(1000점)까지 크래시·멈춤 없이 완주, 모든 룰 인터랙션(폭탄·용·개·마작 소원·티츄/큰티츄·1-2 피니시) UI 정상.
- [ ] D5.1 사운드: 버튼 클릭음·볼륨 패널 슬라이더·백그라운드 음소거 정상.
- [ ] 가로 세이프에어리어(노치/펀치홀 미가림)·방향 잠금.

### 5.4 발견 분류·처리 흐름 (철칙 반영)
플레이테스트에서 문제가 나오면:

- **버그/연출 결함** → 직접 수정(TDD, EditMode 검증).
- **AI 강도 관련(리드/셰딩/밟기 오버라이드)** → **반드시 격리벤치(HeuristicStrengthBench 페어드) 먼저**. 벤치 ≥0(회귀 없음)일 때만 채택. ⚠️ 라이브 EV 오버라이드(리드/셰딩)는 상습 회귀 이력 — 인간 직관이 국소적으론 옳아도 강도 이득은 대개 없음. 관측교정(회귀 없는 체감 개선)은 허용, 강도 주장은 벤치로만.
- **롤아웃 천장 한계(예: AI가 인간 라지티츄 응징 못 함)** → 연구티어로 defer, 명시적 수용.

## 8. 리스크 & 의존성

1. **Android Build Support 미설치 가능성** — R1-a의 실질 첫 관문. 미설치면 Unity Hub 모듈 설치부터.
2. **저사양 미대응(제품 결정)** — 성능 게이트는 S23(현대 기기) 스모크로 단순화. Play 사전 출시 보고서는 R5에서 무료 참고자료로만 활용(게이트 아님).
3. **IP/상표 — 게임명 "Tichu Master" 확정.** 사용자 결정: "Tichu"를 **유지**해 검색 발견성을 살리고 "Master" 접미어로 구분(TichuOne류 패턴). 확인 결과 Play에 "Tichu Master" 동일명 앱 없음(이름 확보 OK). ⚠️ 단 이건 상표 **회피**가 아니라 **유지** 선택 — "Tichu"는 Fata Morgana Spiele/Abacusspiele의 활성 IP이고 공식 라이선스 앱(House Full of Games)도 존재. 즉 발견성↔상표노출 트레이드오프 수용. 원하면 라이선스 문의 경로 존재(선례 있음). 브랜드에 Tichu 유지 → **인게임 "티츄/그랜드 티츄" 콜 명칭 그대로 유지**(변경 불필요). 패키지명은 R2에서 정리(예: `com.kas328.tichumaster`).
4. **강도 회귀 위험** — R1-b 발견을 라이브 오버라이드로 성급히 고치면 회귀. §5.4 격리벤치 철칙 준수.
