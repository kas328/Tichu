# R2 — 빌드/서명 (Release Build & Signing) 설계

- 날짜: 2026-08-19
- 상위 목표: **Google Play 정식 출시** (Tichu Master)
- 이 스펙의 범위: **R2** — 업로드 키 생성·백업, 재현 가능한 서명 AAB 빌드, S23 릴리스 스모크, 비공개 테스트 트랙 업로드 수용
- 선행: R1 통과(2026-08-08 완료, `9d6b5f4`). 후행: 비공개 테스트 공개는 R2 단독으로 불가 — §2 참조.

---

## 1. 배경 & 문제

게임은 완성됐다. Phase 0(룰 엔진) · Phase 1(MVP) · Phase 2(PIMC AI)가 전부 `main`에 머지·푸시됐고, 2026-08-08 R1 출시검증에서 **DoD 4게이트 전부 Pass**로 Phase 1이 공식 종료됐다. 남은 작업은 전부 출시 실무다.

현재 저장소 상태(2026-08-19 실측):

| 항목 | 값 | 상태 |
|---|---|---|
| 브랜치 | `main` = `origin/main` (0/0) | 동기 |
| 식별자 | `Tichu Master` / `com.kas328.tichumaster` | R1에서 확정 |
| minSdk / ABI | 26 / ARM64 단독 | 확인 |
| 스크립팅 | IL2CPP + `stripEngineCode: 1` | 확인 |
| `AndroidTargetSdkVersion` | `0` (Automatic) | **미고정** |
| `androidUseCustomKeystore` | `0`, `AndroidKeystoreName` 빈 값 | **키 없음** |
| 버전 | `bundleVersion 0.1.0` / `versionCode 1` | **출시값 미확정** |
| 빌드 자동화 | `BuildPipeline` 사용처 0건 | **없음** (전부 에디터 GUI 수동) |
| 릴리스 빌드 | 경험 0회 (개발 빌드만) | **미검증** |

`.gitignore`에 `*.apk`·`*.aab`는 있으나 **`*.jks`·`*.keystore`가 없다** — 키 생성 전에 반드시 막아야 한다.

## 2. 로드맵 정정 — 기존 R1~R5 순서가 실제와 다르다

R1 스펙은 `R2 빌드 → R3 자산 → R4 정책 → R5 배포`의 순차 진행을 전제했다. **이 전제는 틀렸다.**

확인 결과 Google Play는 **비공개 테스트 트랙에 게시하려면** 다음이 **모두** 완료돼 있어야 한다:

- App content 선언 — 개인정보처리방침 URL · 광고 여부 · 앱 액세스 · 콘텐츠 등급 설문 · 타겟 연령 · Data safety (= R4)
- 완성된 스토어 등록정보 — 아이콘 · 피처 그래픽 · 스크린샷 2장 이상 · 짧은/긴 설명 (= R3)

즉 **R2·R3·R4는 순차가 아니라 병렬 선행조건**이다.

```
R2 빌드/서명 ─┐
R3 스토어자산 ─┼→ 비공개 테스트 공개 = 14일 시계 시작 → 12명 × 연속 14일 → 프로덕션 권한 신청
R4 정책      ─┘
```

### 2.1 14일 시계 (결정: 개인 계정)

2023-11-13 이후 생성한 **개인** 개발자 계정은 프로덕션 권한 신청 전에 **테스터 12명이 연속 14일간 옵트인**한 비공개 테스트를 통과해야 한다.

- **내부 테스트(internal testing)는 카운트되지 않는다.** 오직 **비공개 테스트(closed testing)** 트랙만 인정된다.
- 12명이 **같은 연속 14일 창** 안에 있어야 하며, 중간 이탈로 12명 아래로 떨어지면 카운터가 리셋된다.
- 구글은 설치가 아니라 **실제 실행(engagement)** 을 본다. 프로덕션 신청 시 받은 피드백과 개선 내용을 서술해야 한다.

**대안 검토 — 조직 계정:** D-U-N-S 번호로 등록한 조직 계정은 이 요건에서 **완전 면제**된다. 그러나 사업자 실체 + D-U-N-S 발급(통상 2~4주, 최대 30일) + 조직 확인 심사가 필요하다. **면제로 아끼는 14일을 얻는 데 2~4주가 든다** → 1인 개발자·단일 앱에는 불리. **사용자 결정: 개인 계정 유지.**

### 2.2 카드 아트의 위치 (결정: 시계 먼저)

스크린샷이 시계 시작의 선행조건이 되면서, 카드 아트가 임계 경로 위로 올라왔다. 두 갈래를 검토했다.

- (가) 아트 먼저 — 완성도 높은 스크린샷으로 시작. 특수 4장 제작 기간만큼 시계가 늦어진다.
- (나) **시계 먼저** — 현재 텍스트 카드로 스크린샷을 찍어 즉시 시계를 켜고, 14일 대기 동안 아트를 완성해 교체.

**사용자 결정: (나).** 14일은 줄일 수 없는 순수 대기이므로 그 시간을 아트로 채우는 편이 총 소요를 최소화한다. 스토어 등록정보 업데이트는 언제든 가능하고, 구글이 프로덕션 승인 심사에서 보는 것은 **신청 시점의** 등록정보다.

## 3. 범위

**포함(R2):**
- `.gitignore` 시크릿 차단
- 업로드 키스토어 생성·백업·복원 검증
- 릴리스 빌드 스크립트 (`targetSdk 36` · AAB · `versionCode` 증분 · 서명)
- 서명 AAB 산출물 실측 검증
- S23 릴리스 빌드 스모크
- Play 개인 계정 생성 · 앱 등록 · **비공개 테스트 트랙 업로드 수용**

**제외(다른 트랙):**
- 테스터 12명 모집 · 14일 시계 관리 · 프로덕션 권한 신청 → 배포 트랙. 단 **모집은 지금부터 병행 권고**(§8).
- 아이콘 · 피처 그래픽 · 스크린샷 · 스토어 문구 → R3 별도 스펙.
- 개인정보처리방침 · Data safety · 콘텐츠 등급 → R4 별도 스펙.
- 카드 아트(56장, 특수 4장 제작) → 별도 스펙. R2와 의존 없음, 병행 진행.

## 4. 목표 & 성공 기준 (DoD)

순서가 곧 의존성이다.

| # | 항목 | 검증 방법 |
|---|---|---|
| 1 | `.gitignore`에 `*.jks`·`*.keystore` 차단 | **키 생성 전 선행.** 커밋 후 `git check-ignore`로 확인 |
| 2 | 업로드 키스토어 생성 + 백업 | **백업본으로 실제 서명이 되는지 복원 테스트** (§6.1) |
| 3 | 릴리스 빌드 스크립트 작성 | 컴파일 0 에러 + 빌드 후 `git status`에 `ProjectSettings.asset` 키 경로 잔존 없음 |
| 4 | 서명 AAB 생성 | 번들 SDK의 `aapt2`로 `targetSdkVersion 36` · `versionCode` 실측, `jarsigner -verify`로 서명 확인 |
| 5 | S23 릴리스 스모크 | 한 판 완주 · 크래시 0 · 코너 UI 정상 · FpsOverlay 미표시 |
| 6 | Play 계정 · 앱 등록 · **AAB 업로드 수용** | 구글이 받아주면 targetSdk · 16KB 정렬 · 서명 · AAB 형식이 전부 통과된 것 |

**6번이 설계의 핵심이다.** 16KB 페이지 정렬 같은 항목의 검증기를 우리가 만들지 않는다 — Play 업로드 자체가 검증기다. 우리 손으로 만드는 게이트는 5번(실기 스모크)뿐이다.

## 5. 빌드 스크립트 설계

**`Assets/_Project/Editor/ReleaseBuild.cs` — 파일 1개, asmdef 0개.** Unity는 `Editor` 폴더를 자동으로 에디터 전용 컴파일하므로 새 어셈블리 정의가 필요 없다(프로젝트의 asmdef 최소화 관례 유지).

### 5.1 설정을 두 종류로 나눈다

| 종류 | 항목 | 처리 |
|---|---|---|
| **영구(커밋)** | `targetSdkVersion = AndroidApiLevel36` · `buildAppBundle = true` · `versionCode` | `ProjectSettings.asset`에 저장·커밋. 프로젝트의 결정이므로 이력에 남는다. |
| **일시(커밋 금지)** | 키스토어 경로 · 비밀번호 · 별칭 | 환경변수로만 주입, 빌드 직후 `try/finally`로 **원복**. |

`AndroidKeystoreName`은 `ProjectSettings.asset`에 직렬화된다(빌드 후 실측: 빈 문자열이 아니라 커스텀 키스토어 없음을 뜻하는 Unity 마커 `'{inproject}: '`로 왕복한다). 원복하지 않으면 **로컬 절대경로가 git에 들어간다**. 비밀번호는 `.asset`에는 직렬화되지 않지만, Unity가 생성하는 `Library/Bee/Android/Prj/IL2CPP/Gradle/launcher/build.gradle`의 `signingConfigs` 블록에 저장소 비밀번호·키 별칭·키 비밀번호가 **평문 리터럴로** 기록되며 빌드가 끝난 뒤에도 그대로 남는다. `Library/`는 `.gitignore`(`/[Ll]ibrary/`)로 막혀 있어 git에는 들어가지 않지만, 그렇다고 "메모리에만 머문다"는 아니다. 따라서 `Library/`는 시크릿을 담은 디렉터리로 취급해야 한다 — 프로젝트 트리를 압축해 공유하거나, 버그 리포트에 첨부하거나, 그대로 클라우드 저장소에 동기화하지 않는다.

### 5.2 시크릿 주입

환경변수 4개: `TICHU_KEYSTORE_PATH` · `TICHU_KEYSTORE_PASS` · `TICHU_KEY_ALIAS` · `TICHU_KEY_PASS`.

하나라도 비면 **빌드를 시작하지 않고 즉시 중단**한다. 서명 없는 AAB가 만들어져 업로드 단계에서야 실패하는 경로를 차단한다. 키스토어 파일 자체는 **저장소 밖**(예: `%USERPROFILE%\.keys\`)에 둔다.

### 5.3 versionCode

빌드마다 +1 하고 저장한다. Play는 동일 `versionCode` 재업로드를 거부하므로, 14일 테스트 중 재빌드가 반복될 때 이 자동화가 실질적 값어치를 낸다. `bundleVersion`은 `1.0.0`으로 확정한다.

### 5.4 단위 테스트를 두지 않는 결정

이 스크립트의 내용은 분기 없는 Unity API 글루이며, `versionCode + 1` 같은 로직에 테스트를 붙이는 것은 형식적이다. 실제 게이트는 **산출물 실측(DoD 4)** 과 **Play 업로드 수용(DoD 6)** 이다.

이는 프로젝트의 TDD 관례에서 벗어나는 유일한 지점이므로 명시해 둔다. 순수 로직을 분리해 `Tichu.BuildTools` asmdef + 테스트로 만드는 대안이 있으나, 30줄 규모에는 과하다고 판단했다.

### 5.5 확인된 API 지원 (Unity 6000.3.17f1)

에디터 설치본에서 직접 확인:

- `AndroidApiLevel36` — `UnityEditor.dll`, `UnityEditor.CoreModule.dll`에 정의됨
- `useCustomKeystore` · `keystoreName` · `keystorePass` · `keyaliasName` · `keyaliasPass` · `buildAppBundle` — API 문서(`UnityEditor.xml`)에 존재
- 번들 Android SDK에 `android-36` 플랫폼 + `build-tools 36.0.0` 설치됨 → **추가 설치 불필요**

## 6. 실행 순서와 게이트

순서가 곧 안전장치다. 1번을 건너뛰면 2번에서 사고가 난다.

| 단계 | 작업 | 주체 | 게이트 |
|---|---|---|---|
| 1 | `.gitignore` 시크릿 차단 → 커밋 | Claude | — |
| 2 | `keytool`로 업로드 키스토어 생성 → 저장소 밖 배치 → 백업 | **사용자** (비밀번호 취급) | 백업본으로 서명 성공 |
| 3 | `ReleaseBuild.cs` 작성 + `targetSdk 36`·AAB 설정 커밋 | Claude | 컴파일 0 에러 |
| 4 | 서명 AAB 빌드 → 산출물 실측 | Claude (배치 모드) | targetSdk 36 · versionCode · 서명 확인 |
| 5 | S23 설치 · 릴리스 스모크 | **사용자** | 완주 · 크래시 0 · 코너 UI 정상 |
| 6 | Play 계정 · 앱 등록 · 비공개 트랙 업로드 | **사용자** | 구글 수용 |

### 6.1 키스토어 백업 요건 (DoD 2의 구체 기준)

"백업했다"의 기준을 모호하게 두지 않는다. 세 가지를 모두 만족해야 통과다.

1. **서로 다른 물리적 위치 2곳** — 개발 PC가 사라져도 살아남아야 하므로 최소 한 곳은 PC 외부(오프라인 매체 또는 클라우드).
2. **비밀번호는 키스토어 파일과 분리 보관** — 같은 곳에 두면 백업이 아니라 단일 실패점이 하나 더 생기는 것에 불과하다.
3. **복원 테스트** — 백업본을 다른 경로에 복사해 그것으로 실제 서명이 되는지 확인한다. 열어보지 않은 백업은 백업이 아니다.

### 6.2 Play App Signing

신규 앱은 Play App Signing이 적용된다. 즉 §6의 2단계에서 만드는 키는 **업로드 키**이고, 사용자에게 배포되는 APK의 서명 키는 구글이 보관한다. 6단계 앱 등록 시 기본 경로를 그대로 따른다(별도 선택 없음).

## 7. 리스크

1. **IL2CPP 스트리핑 회귀** — 개발 빌드는 통과했으나 릴리스 빌드는 처음이다. VContainer(DI)·R3가 리플렉션을 쓰므로 타입이 잘리면 **런타임에만** 터진다. DoD 5(실기 스모크)가 이를 잡는 유일한 그물이며, 발생 시 `link.xml`로 대응한다.
2. **키스토어 경로 유출** — §5.1의 `finally` 원복이 방어선. DoD 4 이후 `git status`로 `ProjectSettings.asset`에 경로가 남지 않았는지 확인한다.
3. **16KB 페이지 정렬 / API 36 거부** — 자체 검증기를 만들지 않는다. DoD 6 업로드가 판정한다. 거부되면 Unity 빌드 설정으로 되돌아온다.
4. **되돌릴 수 없는 항목** — 패키지명(확정) · 계정 유형(개인 확정) · `versionCode` 재사용 불가. 실수 시 복구 경로가 없다.
5. **업로드 키 분실** — Play App Signing 하에서는 업로드 키 **재설정 요청**으로 복구 가능(승인 1~2 영업일). "영구 갱신 불가"는 Play App Signing 미가입 상태에만 해당한다. 그래도 재설정은 시간·번거로움 비용이므로 백업(DoD 2)은 유지한다.

## 8. 병행 트랙 (R2 밖, 지금부터 시작 권고)

- **테스터 15~18명 명단 확보** — 12명은 최소값이고 이탈 시 카운터가 리셋되므로 여유가 필요하다. 조달 경로: 개발자 교환 커뮤니티(`r/AndroidAppTesters` 등) · 지인 · 보드게임 커뮤니티. 본인 계정 다중 사용은 의심 패턴으로 거절 위험이 있어 배제한다. 리드타임이 긴 사람 일이므로 코드 작업과 병행하면 DoD 6이 끝나는 날 바로 시계를 켤 수 있다.
- **카드 아트** — 별도 스펙. 14일 대기 중 완성해 스크린샷 교체.
- **R3 · R4** — 별도 스펙. 시계를 켜려면 R2와 함께 완료돼야 한다.
