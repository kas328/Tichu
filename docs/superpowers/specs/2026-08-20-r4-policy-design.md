# R4 — 정책 선언 (Store Policy Declarations) 설계

- 날짜: 2026-08-20
- 상위 목표: **Google Play 정식 출시** (Tichu Master)
- 이 스펙의 범위: **R4** — 개인정보처리방침 · Data safety · 콘텐츠 등급 · 타겟 연령 · 앱 액세스 · 광고 선언
- 선행: R2 완료(2026-08-20, `b75d09c`). 병행: R3(스토어 자산). **R3·R4가 모두 끝나야 비공개 테스트를 공개할 수 있고, 그때 14일 시계가 시작된다.**

## 1. 배경 & 문제

R2에서 서명 AAB를 만들고 실기 검증까지 마쳤다. 그러나 **AAB만으로는 비공개 테스트 트랙을 공개할 수 없다.** Play는 트랙 게시 전에 App content 선언(이 스펙)과 완성된 스토어 등록정보(R3)를 모두 요구한다.

R4의 본질은 코딩이 아니라 **정확한 사실 선언**이다. 여기서 틀리면 대가가 크다 — 허위 신고는 앱 정지 사유이고, Data safety 불일치는 실제로 앱이 내려가는 사유다. 그래서 이 스펙은 답변을 **추측하지 않고 산출물과 코드로 검증한 뒤** 확정한다.

## 2. 사실 검증 결과 (R4-A) — 이 앱은 아무 데이터도 수집하지 않는다

모든 답변의 근거다. 검증 일자 2026-08-20, 대상은 실제 출시 산출물 `TichuMaster-1.0.0-2.aab` 및 `main` 브랜치 코드.

| 확인 항목 | 방법 | 결과 |
|---|---|---|
| 앱 권한 | `aapt2 dump badging` (실제 산출물) | `android.permission.INTERNET` 단 하나 + Unity 표준 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`. **광고 ID(`AD_ID`)·위치·저장소·카메라·마이크 전부 없음** |
| 네트워크 코드 | `Assets/_Project` 전체 검색 | `UnityWebRequest`·`HttpClient`·`WebClient`·`System.Net`·`Socket`·`DownloadHandler` **0건** |
| 분석·광고 SDK | 같은 검색 | `Analytics`·`Firebase`·`AdMob`·`Advertisement` **0건** |
| Unity 클라우드 서비스 | `ProjectSettings/UnityConnectSettings.asset` | Analytics `0` · Ads `0` · Purchasing `0` · Insights `0` · PerformanceReporting `0` · CloudDiagnostics(Crash) `0` — **전부 비활성** |
| 로컬 저장 | `PlayerPrefs` 사용처 | `VolumeSettings.cs`의 BGM·효과음 볼륨 `float` 2개뿐. **기기를 벗어나지 않음** |
| 개발 도구 유출 | MCP 패키지 asmdef·소스 | 네트워크를 여는 `MCPForUnity.Editor`는 `includePlatforms: ["Editor"]`로 **빌드 미포함**. 빌드에 들어가는 `MCPForUnity.Runtime`은 호환 shim·직렬화 헬퍼뿐으로 `RuntimeInitializeOnLoadMethod`·`MonoBehaviour`·네트워크 코드가 **전무** → 스스로 실행되지 않는 수동 코드 |

**결론: 수집 0 · 공유 0 · 계정 없음 · 광고 ID 미사용.**

`INTERNET` 권한은 우리 코드가 쓰지 않는데도 Unity가 기본으로 넣는다. 정책 위반이 아니고 Data safety와도 무관하지만(권한 보유 ≠ 수집), 스토어에 "전체 네트워크 액세스"로 표시된다. 제거는 빌드 설정 영역이라 **R4 범위 밖**으로 두고 기록만 한다.

## 5. 개인정보처리방침

### 5.1 호스팅 (결정)

**`kas328/Tichu` 저장소의 `gh-pages` 브랜치**에 방침 파일만 두고, GitHub Pages를 그 브랜치의 루트로 연결한다.

브랜치 구조는 이렇게 고정한다 — `main`의 이력과 완전히 분리된 orphan 브랜치로 만들어 게임 소스가 섞이지 않게 한다.

```
gh-pages (orphan)
├── privacy/index.html    → https://kas328.github.io/Tichu/privacy/
└── .nojekyll             → Jekyll 처리 비활성(정적 HTML 그대로 서빙)
```

`index.html` 파일명이라 URL 끝에 파일명이 붙지 않는다. `.nojekyll`을 두는 이유는 Jekyll이 개입해 예기치 않게 파일을 변환하거나 밑줄로 시작하는 경로를 숨기는 것을 막기 위해서다.

`main`의 `/docs` 폴더를 Pages 소스로 쓰지 않는 이유: 그 폴더에는 `docs/superpowers/specs`·`plans`(설계·구현 계획·벤치 결과)가 들어 있어, Pages를 켜면 **내부 개발 문서가 웹 주소를 갖고 검색엔진에 색인된다.** 저장소가 이미 공개라 새로운 정보 노출은 아니지만, 저장소 파일은 검색에 잘 걸리지 않는 반면 Pages 사이트는 정식 웹사이트로 크롤링된다. 보안 문제가 아니라 **정돈과 검색 노출**의 문제이며, 브랜치를 분리하면 비용 없이 사라진다.

### 5.2 내용 (한국어 + 영어 병기)

수집이 없으므로 짧다. 다음을 반드시 포함한다.

| 항목 | 내용 |
|---|---|
| 수집하는 정보 | **없음.** 개인정보를 수집·전송·저장하지 않는다 |
| 기기에 저장되는 것 | 음량 설정값(BGM·효과음). 기기를 벗어나지 않으며 앱 삭제 시 함께 지워진다 |
| 제3자 제공 | 없음. 분석·광고·크래시 리포팅 SDK를 사용하지 않는다 |
| 광고 | 현재 없음 |
| 아동 개인정보 | 수집하지 않으므로 아동 정보도 수집하지 않는다 |
| 문의처 | `kas328@naver.com` |
| 시행일 / 변경 고지 | 시행일 명시, 변경 시 이 페이지에서 고지 |

**형식: 페이지 1개에 한국어 전문을 먼저, 이어서 영어 전문을 싣는다**(별도 URL을 만들지 않는다). Play에 등록하는 방침 URL은 하나뿐이어야 관리가 단순하고, URL이 여럿이면 하나가 죽었을 때 알아채기 어렵다. 영어를 병기하는 이유는 구글 심사자가 영어로 읽기 때문이다.

### 5.3 연락처 (결정)

`kas328@naver.com`. Play는 스토어 등록정보에 공개 연락처 이메일을 요구하므로 어차피 공개된다. Play Console 계정 자체는 구글 계정이어야 하지만 공개 연락처는 달라도 무방하다.

## 8. 타겟 연령 · 앱 액세스 · 광고

- **타겟 연령: 13세 이상**(결정). 13세 미만을 하나라도 포함하면 **Google Play 가족 정책**이 적용되어 추가 선언·심사가 붙는다. 우리는 광고도 수집도 없어 요건 자체는 충족하지만 심사가 길어지고, 티츄는 규칙이 복잡한 전략 카드게임이라 13세 이상 선언이 실제 이용층과도 맞다. 콘텐츠 등급(전체이용가)과 타겟 연령(13+)이 다른 것은 정상이다 — 전자는 콘텐츠 수위, 후자는 대상 의도다.
- **앱 액세스: 제한 없음.** 로그인·잠긴 콘텐츠가 없으므로 심사용 테스트 계정이 필요 없다.
- **광고: 현재 없음.** ⚠️ **사용자가 향후 광고 도입 가능성을 밝혔다.** 광고 SDK는 광고 ID를 수집하므로 도입 시 §6의 "수집 없음"이 **거짓이 된다.** 광고를 넣는 업데이트에서는 Data safety를 반드시 다시 신고하고, 개인정보처리방침도 갱신해야 한다. 이는 정상 절차이며 지금의 선언을 막지 않는다.

## 9. 리스크

1. **방침 URL이 죽으면 앱이 내려갈 수 있다.** 앱이 스토어에 있는 한 URL은 계속 열려 있어야 한다. `gh-pages` 브랜치 삭제·저장소 이름 변경·저장소 비공개 전환이 전부 URL을 깨뜨린다.
2. **광고 도입 시 재신고 의무를 잊는 것.** §8에 기록했다.
3. **허위 신고 = 앱 정지.** §2에서 추측 대신 산출물 권한과 코드로 검증한 이유다.
4. **Pages 활성화는 사람 손이 필요하다.** 저장소 Settings → Pages에서 소스를 `gh-pages` 브랜치로 지정하는 조작은 웹 UI에서만 가능하다. 브랜치와 파일은 준비해 두고 활성화만 사용자가 한다.
5. **`INTERNET` 권한 표시.** 스토어 권한 목록에 "전체 네트워크 액세스"가 뜬다. 정책 위반은 아니나 이용자가 의아해할 수 있다. 제거 검토는 별도 판단으로 남긴다.
