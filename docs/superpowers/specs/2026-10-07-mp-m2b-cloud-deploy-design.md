# 멀티플레이 M2b — 클라우드 배포 · `wss://` (설계 스펙)

- **날짜:** 2026-10-07
- **트랙:** Phase 3 멀티플레이. M2(`0450e2d`, 로컬 서버) 다음 증분.
- **상태:** 설계 승인됨(brainstorming). 구현 계획 수립 전.
- **배경:** M2 스펙 `2026-10-07-mp-m2-websocket-server-design.md` §9(M2b = 클라우드 배포 · TLS · 도메인/인증서)
- **상위 결정(2026-10-07):** 출시 버전에 **랜덤 매칭 멀티플레이를 넣는다.** 순서 = M2b 배포 → M3 다중 방 + 매칭 대기열 → M5 이탈 처리(턴 타이머·재접속·AI 인계) → 정책 재신고. M6 계정·랭킹은 출시 범위 밖이어도 된다. **실기 빌드는 마일스톤마다 한 번** 한다.

## 1. 확정된 결정

1. **호스팅 = AWS Lightsail 서울(ap-northeast-2), Ubuntu 24.04 LTS, 메모리 1GB 플랜(월 약 $7).** 지금 서버는 프로세스 하나가 매치 상태를 메모리에 30~60분씩 들고 있는 구조라, 계속 켜져 있는 VM이 맞다. 0.5GB 플랜도 돌아가지만 Caddy·.NET·PIMC가 함께 메모리를 써서 메모리 부족으로 죽는 상황을 추적하는 비용이 차액보다 크다.
   - 기각: Vultr 서울(월 $12부터, 이 단계에선 이득 없음) · Oracle 무료(서울·춘천 용량 부족, 2026-08 한도 축소, 7일 저사용 시 회수) · Fly.io(서울 리전 없음, 배포마다 재시작돼 진행 중인 판이 끊김).
   - **Supabase는 게임 서버로 쓸 수 없다.** Edge Functions는 연결 최대 150초(무료)/400초(유료), 요청당 CPU 2초, TypeScript 전용이다. 30~60분 매치·PIMC·C# 룰 엔진 중 어느 것도 맞지 않는다. Realtime을 중계로만 쓰면 규칙 판정을 누군가의 폰이 맡아야 해서 Photon을 기각한 이유(호스트 이탈 시 판 소멸, 손패 노출)가 그대로 돌아온다. **Supabase의 자리는 M6 계정·랭킹·전적이다.**
2. **주소 = 직접 소유한 도메인 + Caddy.** 이 주소는 출시 앱 안에 고정되고, 앱이 스토어에 있는 동안 살아 있어야 한다(개인정보처리방침 URL과 같은 성격). 도메인을 직접 갖고 있으면 서버를 옮기거나 IP가 바뀌어도 DNS만 고치면 된다. Caddy가 Let's Encrypt 인증서를 자동으로 발급·갱신한다.
   - 도메인은 **AWS(Lightsail/Route 53)에서 산다.** 계정과 콘솔이 하나라 브라우저 조작 단계가 줄어 실수가 줄고, DNS는 Lightsail에서 무료로 관리된다. 이름은 실행 시 후보를 검색해 정한다. 앱 이름이 바뀔 수 있으므로(상표 이슈) **"tichu"가 들어가지 않는 이름**을 권한다. 접속 주소는 `wss://play.<도메인>/ws`.
   - 기각: 무료 서브도메인(DuckDNS 등 — 그 서비스가 멈추면 출시 앱 전체가 접속 불가) · Cloudflare 경유(경로가 하나 늘어 긴 WebSocket이 가끔 끊길 수 있고, 지금 규모에서 DDoS 방어는 불필요. 같은 도메인으로 나중에 바꿔 붙일 수 있다).
3. **배포 = PC에서 실행하는 수동 스크립트 `tools/deploy-server.ps1`.** 배포는 서버를 재시작해 진행 중인 판을 끊으므로, 사람이 원할 때(판이 없을 때)만 일어나야 한다. linux-x64 **self-contained** publish라 서버에 .NET을 설치하지 않는다.
   - 기각: GitHub Actions 자동 배포(푸시마다 판이 끊김, SSH 키를 GitHub에 맡겨야 함) · Docker(서버 하나·프로세스 하나인 지금 규모에선 관리할 것만 늘어남).
4. **프로토콜 버전 확인을 이번에 넣는다.** 서버가 인터넷에 올라가는 순간부터 서버 업데이트와 폰에 깔린 APK 업데이트가 따로 논다. M3에서 메시지 형식이 바뀌면 구버전 APK가 알 수 없는 오류를 낸다.
5. **운영 작업은 Claude가 사용자 Chrome을 제어해 진행한다**(Claude in Chrome). 사용자는 로그인·2단계 인증·결제 정보 입력·구매 확정만 한다. 상세 역할은 §6.

## 2. 목표 (M2b)

M2 서버를 클라우드에 올려, 폰이 **어느 네트워크에서든** `wss://`로 접속해 매치를 끝까지 둘 수 있게 한다. **게임 로직 · `MatchSession` · `RemoteAgent` · 매치 흐름 · 싱글플레이 동작은 바꾸지 않는다.** 서버는 지금처럼 **방 하나, 한 번에 한 매치**다(방 여러 개는 M3).

## 4. 구조

```
 폰 / 에디터 ──── wss://play.<도메인>/ws?v=1 (443) ────▶  Lightsail 서울 · Ubuntu 24.04 · 고정 IP
                                                          ├─ Caddy (systemd)
                                                          │    인증서 자동 발급·갱신
                                                          │    443 → 127.0.0.1:7777 리버스 프록시(WebSocket 자동 처리)
                                                          └─ tichu-server (systemd, Restart=always)
                                                               Tichu.Server --host 127.0.0.1 --port 7777
                                                               --seats 0,2 --difficulty Hard --target 1000
```

- **방화벽(Lightsail):** TCP 22(SSH) · 80(인증서 발급 HTTP 챌린지 + HTTPS 리다이렉트) · 443만 연다. 7777은 열지 않고, 서버도 루프백에서만 받는다(이중 방어).
- **systemd 서비스 `tichu-server`:** 전용 계정 `tichu`로 실행, `Restart=always`, 부팅 시 자동 시작. 로그는 기존 콘솔 출력을 journald가 받는다(`journalctl -u tichu-server`). 종료 시간 제한은 서버의 기존 `ShutdownTimeout` 3초와 어울리게 둔다.
- **배치 경로:** `/opt/tichu/server/`(publish 결과물). 배포 스크립트는 새 결과물을 옆 디렉터리에 올린 뒤 바꿔치기하고 재시작한다. 실패하면 이전 디렉터리로 되돌릴 수 있게 한 판 전 것은 남긴다.
- **Caddyfile:** `play.<도메인> { reverse_proxy 127.0.0.1:7777 }` 수준. 사이트 루트 등 다른 경로는 두지 않는다.

## 5. 코드 수정 (TDD)

### 5.1 `ServerAddress` 포트 버그 수정 (M2b를 막는 버그)

현재 `TryParse`는 포트가 생략되면(`IsDefaultPort`) 스킴과 상관없이 7777을 붙인다. 그래서 `wss://play.<도메인>`이 `wss://play.<도메인>:7777/ws`가 되어 Caddy(443)에 닿지 못한다.

- `ws://` + 포트 생략 → 7777(지금과 같음, 같은 Wi-Fi 개발용). 스킴 생략도 `ws`로 보므로 `192.168.0.5` 입력은 그대로 동작한다.
- `wss://` + 포트 생략 → 443 그대로.
- 포트를 명시하면 그대로, 경로 생략 → `/ws`(지금과 같음).
- `core/src/Tichu.Net/ServerAddress.cs` 수정 → Unity 미러 동기.

### 5.2 서버 `--host` 옵션

- `ServerOptions.Host`, 기본 `0.0.0.0`(지금 PC 실행 방식 그대로). CLI `--host <주소>`.
- `Program.cs`가 `$"http://{opt.Host}:{opt.Port}"`로 바인딩하고, 사용법 문구에 추가.
- 클라우드에선 systemd가 `--host 127.0.0.1`을 넘긴다.

### 5.3 프로토콜 버전 확인

- **`Tichu.Net`에 `ProtocolVersion.Current = 1`** 상수(Unity로 미러됨). 이후 와이어 형식이 바뀌는 변경(M3 등)은 이 값을 올린다.
- **클라이언트:** `WebSocketClientTransport.ConnectAsync`가 받은 URI에 `v=<Current>` 쿼리를 붙여 접속한다. 모든 클라이언트(앱 · E2E 테스트)가 이 한 곳을 지나므로 호출부는 바뀌지 않는다. 주소 입력값(`PlayerPrefs`)에는 버전을 저장하지 않는다.
- **서버:** `/ws` 핸들러에서 **좌석을 배정하기 전에** 쿼리 `v`를 확인한다. 맞으면 지금처럼 `transport.HandleAsync`. 다르거나 없으면 WebSocket을 받아들인 뒤 `SessionFaulted("앱을 업데이트해 주세요 (서버 프로토콜 v<서버값>)")` 하나를 보내고 정상 종료하며, **좌석·대기실 상태를 건드리지 않는다.** 거절은 로그에 남긴다(받은 버전 포함).
  - HTTP 상태 코드로 거절하지 않는 이유: `ClientWebSocket`은 업그레이드 실패를 일반 예외로만 올려서 사용자에게 "서버에 연결할 수 없습니다"로 보인다. `SessionFaulted`는 클라이언트가 이미 "폴트 문구 표시 → 메뉴 복귀"(`d10e177`)로 처리하므로 **새 UI가 필요 없다.**
  - 버전 쿼리가 없는 현재 APK(M2 빌드)도 같은 경로로 안내를 받는다(DoD 6).
- 버전 문자열은 정수만 받는다. 파싱 실패도 "불일치"로 본다.

### 5.4 이번에 안 하는 것 (YAGNI)

- 접속 화면(NetJoin)에 운영 주소 미리 채우기 — 테스터는 한 번 입력하면 기기에 기억된다. 출시 빌드에 주소를 넣는 일은 M4 로비.
- 헬스체크 엔드포인트 · 모니터링/알림 · 로그 수집 · 다중 서버 · 무중단 배포.
- 접속 IP 로깅(`X-Forwarded-For`) — 모든 접속이 Caddy(127.0.0.1)에서 오는 것으로 보이지만 지금은 필요 없다.
- 모르는 사람의 좌석 점유 방지 — 도메인을 아는 사람만 들어오는 단계이고, M3의 방·초대 코드가 근본 해결이다.

## 6. 운영 절차와 역할

사용자 Chrome을 Claude가 제어한다(Claude in Chrome). **되돌릴 수 없거나 비용이 드는 클릭 직전에는 멈추고 확인을 받는다.** 단계마다 스크린샷과 명령(`nslookup` · `curl` · `ssh`)으로 결과를 검증한다.

| 사용자 | Claude |
|---|---|
| AWS 로그인 · 2단계 인증 | Lightsail 인스턴스 생성(서울 · Ubuntu 24.04 · 1GB) · 고정 IP 연결 · 방화벽 규칙 |
| 결제 정보 입력 · 구매 확정 클릭(Claude는 결제 화면에서 멈추고 금액을 보여준다) | 도메인 후보 검색 · DNS A 레코드(`play` → 고정 IP) |
| 비용이 드는 단계마다 "진행" 승인 | SSH 키 다운로드 → `C:\Users\user\.keys\`에 보관 |
| | 서버 초기 세팅 스크립트(1회): Caddy 설치 · `tichu` 계정 · 디렉터리 · systemd 유닛 · Caddyfile |
| | `tools/deploy-server.ps1` · 운영 안내서(runbook) |

- **비밀 정보:** SSH 키는 `C:\Users\user\.keys\`에만 두고 저장소에 넣지 않는다. 스크립트는 키 경로와 호스트를 **환경변수**로 받는다(R2 업로드 키와 같은 방식). 저장소에 들어가는 것은 스크립트와 템플릿뿐이다.
- **SSH로 실제 서버에 명령을 실행하는 첫 회에는 사용자 확인을 받는다.**
- **비용:** 인스턴스 월 약 $7 + 도메인 연 $13~15 정도(실행 시 실제 금액 확인).

## 7. 테스트

- **`ServerAddressTests`(dotnet, Unity 미러):** `ws` 포트 생략 → 7777 · `wss` 포트 생략 → 443 · 명시 포트 유지(`wss://h:8443`) · 경로 생략 → `/ws` · 스킴 생략 → `ws`+7777 · 기존 거절 케이스(http 등) 유지.
- **`ServerOptions`:** `--host` 파싱, 기본값 `0.0.0.0`, 값 누락 시 예외.
- **버전 확인(`Tichu.Server.Tests`):**
  - `v=Current` → 좌석 배정(`Lobby` 수신).
  - `v` 다름 · `v` 없음 · `v=abc` → `SessionFaulted`(업데이트 문구) 수신 후 연결 닫힘.
  - **불일치 접속은 좌석을 차지하지 않는다:** 불일치 접속 뒤에 들어온 정상 접속자가 첫 좌석(`--seats` 첫 값)과 `Lobby 1/N`을 받는다.
  - `WebSocketClientTransport.ConnectAsync`가 실제로 `v`를 붙인다(서버 측에서 받은 쿼리로 확인).
- **기존 테스트 유지:** 원시 `ClientWebSocket`으로 접속하는 기존 서버 테스트는 테스트 서버 헬퍼의 `WsUri`에 `v=Current`를 포함시켜 의미를 그대로 유지한다.
- **음성 대조:** 각 수정의 핵심 줄(포트 분기 · 버전 검사)을 되돌리면 해당 테스트만 실패하는지 확인한다.
- ⚠️ Unity는 NUnit 3.5 — 미러되는 테스트에 NUnit 4 전용 API 금지. dotnet 그린 ≠ Unity 그린이므로 Unity EditMode를 따로 돌린다.

## 8. 위험과 대응

- **Android IL2CPP의 `wss` 인증서 검증:** Unity TLS가 Let's Encrypt 체인을 받아들이는지는 실기에서만 확인된다. 에디터 → S23 순으로 확인하고, 막히면 원인을 조사한다(추측 수정 금지).
- **배포 = 진행 중인 판 종료:** 판이 없을 때만 배포한다. runbook에 명시하고, 배포 스크립트는 실행 전에 확인 문구를 띄운다.
- **버스트형 CPU 크레딧:** M2b는 동시 매치 1이라 문제가 되지 않는다. 동시 매치 수 측정과 플랜 결정은 M3.
- **SSH 키 · 인스턴스 분실:** 키는 업로드 키와 같은 폴더에서 백업 대상에 포함한다. 서버에는 복구할 상태가 없다(매치는 메모리, 영속 데이터 없음). 세팅 스크립트로 재구축 가능해야 한다.
- **도메인 갱신 누락:** 자동 갱신을 켠다. 만료되면 출시 앱 전체가 접속 불가.

## 9. 범위 밖

- **M3** 방 · 초대 코드 · 한 서버 다중 매치 · 매칭 대기열 · 동시 매치 용량 측정
- **M4** 로비 UI · 출시 빌드 주소 고정 · 거부 메시지 표출 · 연결 상태 표시
- **M5** 턴 타이머 · 재접속 · AI 인계 · 무중단 배포(재접속이 있어야 의미 있음)
- **M6** 계정 · 랭킹 · Supabase
- 출시 전 정책 재신고(Data safety · 콘텐츠 등급 · 개인정보처리방침) — 온라인 대전이 출시에 들어가는 시점
