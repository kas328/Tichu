# 멀티플레이 M5 — 턴 타이머 · AI 인계 · 재접속 (설계 스펙)

- **날짜:** 2026-10-09
- **트랙:** Phase 3 멀티플레이. M3(랜덤 매칭·다중 방, main `ca634a9`) 다음 증분.
- **상태:** 설계 승인됨(brainstorming). 구현 계획 수립 전.
- **브랜치:** `feat/mp-m5` ← main.
- **목적:** 낯선 사람과 랜덤 매칭되는 출시 환경에서 **한 사람 때문에 판이 깨지지 않게** 한다. 잠수하면 시간 초과로 넘어가고, 나가면 AI가 이어받고, 돌아오면 자기 자리로 돌아간다. 출시 전 필수 단계(M3 결과 보고 §4).

## 1. 확정된 결정

1. **턴 타이머 = 결정 한 번에 30초.** 큰 티츄·교환·차례·용 양도 모두 같은 30초. 시간이 다 되면 **그 한 수만** 대리 AI가 둔다.
2. **AI 인계 + 복귀 허용.** 연결이 끊기거나 **연속 2번** 시간 초과면 좌석이 "자리 비움"이 되고, 대리 AI(Hard)가 즉시 둔다. 사람이 아무 액션을 보내거나 [돌아가기]를 누르거나 재접속하면 **다음 질문부터** 다시 사람이 둔다.
3. **자동 복귀.** 기기 식별자(무작위 GUID, `PlayerPrefs`)로 알아본다. 연결이 잠깐 끊기면 앱이 알아서 재접속해 같은 자리로 돌아가고, 앱을 완전히 껐다 켜도 "온라인 대전"을 누르면 진행 중인 판으로 바로 들어간다. 묻는 화면 없음.
4. **방에 연결된 사람이 0명이면 2분 기다렸다 종료.** 그동안 판을 멈춘다(사람 좌석 차례에서 대기, AI끼리 계속 두지 않음). 2분 안에 누가 돌아오면 이어서 진행한다.
5. **M3 규칙 "한 명 나가면 그 방 종료"는 없앤다.** 방은 매치 종료 또는 사람 0명 2분 경과로만 닫힌다.
6. **구조 = 원격 좌석 안의 대리 AI(접근안 A).** `RemoteAgent`가 그 좌석 전용 `PacedPimcAgent`(Hard)를 품고, 사람이 없을 때 결정을 넘긴다. 게임 엔진·`GameDriver`·순수 AI 좌석은 바뀌지 않는다 → AI 회귀 벤치·오라클이 그대로 유효하다.
   - 기각 B(드라이버에서 좌석 에이전트 교체): core `GameDriver` 수정, 복귀 시 재교체, AI 전용 경로(시뮬·오라클)에 영향.
   - 기각 C(서버 안 봇 클라이언트): PIMC 는 전체 `GameState` 로 결정하는데 클라이언트엔 마스킹 뷰뿐 — AI 재작성 필요.

## 2. 좌석 상태와 서버 동작

```
 [사람 있음] ──30초 초과──▶ 그 한 수만 대리 AI (연속 2번이면 ▼)
     ▲                                          │
     │ 아무 액션 / Resume / 재접속                ▼
     └──────────────────────────────── [자리 비움: 대리 AI가 즉시 둠]
                                        ▲
                 연결 끊김 ──────────────┘
```

- **사람 있음:** 질문마다 30초 대기. 초과하면 그 질문은 대리 AI 가 답하고 연속 초과 카운트 +1. 사람이 답하면 카운트 0.
- **자리 비움:** 질문이 오면 30초를 기다리지 않고 대리 AI 가 즉시 답한다.
- **복귀 트리거:** 그 좌석에서 온 아무 유효 액션, `Resume`, 재접속. 복귀 후 다음 질문부터 사람이 둔다(이미 대리 AI 가 답한 질문은 되돌리지 않는다).
- **대리 AI:** 좌석마다 하나, 매치 내내 재사용. 사람이 둔 교환 카드 등 대리 AI 가 모르는 정보는 그냥 없는 것으로 다룬다(정확도만 조금 낮아짐, 동작은 정상).
- **대리 AI 계산 위치:** 그 좌석을 묻고 있는 세션 스레드에서 동기로. 새 스레드 없음. `PacedPimcAgent` 의 연산·지연 겹침 그대로.
- **사람 0명(멈춤):** 방에 연결된 사람 좌석이 하나도 없으면, 사람 좌석 차례에서 원격 좌석이 대리 AI 로 두지 않고 기다린다. 방은 0명이 된 시각을 기록하고, 서버 1초 틱에서 2분이 지나면 세션을 멈추고 방을 닫는다(방송 대상 없음). 그 전에 누가 재접속하면 이어서 진행한다.

## 3. 프로토콜 (v2 → v3)

- `ProtocolVersion.Current = 3`. v2 앱은 기존 관문이 업데이트 안내 후 닫는다.
- **접속 URI:** `?v=3&id=<기기 식별자>`. `id` 는 클라이언트가 처음 실행 때 만든 GUID(`PlayerPrefs` 저장). 없거나 형식이 틀리면 접속 거절(업데이트 안내와 같은 방식의 사유).
- **`Awaiting` 추가 필드:**
  - `AskId`(long) — 서버가 그 좌석에 묻는 질문의 일련번호(좌석별 증가).
  - `SecondsLeft`(int?) — 이 질문의 남은 초. 시계 차이를 피하려 절대 시각(`DeadlineUtc`) 대신 쓴다. 앱이 받은 시각부터 직접 센다. 자리 비움·사람 0명 대기 중이면 null.
- **`ClientAction` 추가 필드:** `AskId`(long) — 답하는 질문의 번호. 0 = 번호 없음.
- **`PlayerView` 추가 필드:** `Away`(bool[4]) — 좌석별 자리 비움(AI 대행) 여부.
- **새 클라이언트 액션 `Resume`** — 자리 비움 상태에서 [돌아가기]. 서버는 좌석을 사람 있음으로 바꾸고 아무것도 적용하지 않는다.
- **재접속 시 `Lobby`:** 기존 `Lobby(내 좌석, 사람 수, 사람 수)` 에 **매치 누적 점수**를 함께 싣는다(기존 `TeamA`/`TeamB` 필드 재사용, 절대 좌석 기준 — 클라이언트가 홀수 좌석이면 뒤집는다). 이어서 현재 상태 스냅샷 `StateUpdate`(내 차례면 `Awaiting` 포함).
- 열거형 이름 문자열 · 카드 정규 재생성 등 M2 직렬화 규칙 유지.

### 3.1 늦게 도착한 답 거부

시간 초과로 대리 AI 가 둔 직후 사람의 답이 늦게 도착해 **다음 질문에 엉뚱하게 적용되는 것**을 막는다.

- **차례·용 양도:** 답의 `AskId` 가 지금 묻고 있는 질문과 다르면 `ActionRejected("stale answer")`. 클라이언트는 이미 거부를 처리한다(프롬프트 정리).
- **큰 티츄·교환:** 앱이 서버 질문보다 먼저 답하는 구조(`_earlyPrompt`)라 `AskId` = 0 을 허용한다. 대신 **이번 라운드에 그 좌석의 결정이 이미 끝났으면**(사람이든 대리 AI 든) 그 종류의 늦은 답을 거부한다.
- **차례 밖 폭탄·작은 티츄:** 지금처럼 예약 경로(`AskId` 검사 없음).

## 4. 서버 접속 처리

| 상황 | 처리 |
|---|---|
| 이 `id` 의 좌석이 진행 중인 방에 있음 | 대기열을 건너뛰고 그 좌석에 재연결. 방 잠금 안에서: 링크 교체 → 원격 좌석의 액션 순번 기준(`_lastSeq`) 초기화 → 좌석을 사람 있음으로 → `Lobby`(+누적 점수) → 스냅샷 `StateUpdate`. |
| 같은 `id` 의 옛 연결이 아직 살아 있음 | 옛 연결을 닫고(사유 "다른 곳에서 접속") 새 연결로 교체. 옛 연결의 늦은 끊김은 좌석에 영향 없음(소속이 바뀌었으므로). |
| 같은 `id` 가 이미 대기열에 있음 | 옛 대기 연결을 닫고 새 연결로 교체(인원 중복 없음). |
| 그 밖 | M3 처럼 대기열. |

- 매치메이커가 진행 중인 방의 **`id → 방`** 목록을 자기 잠금 안에 둔다. 방이 끝나면 지운다.
- **액션 순번 초기화 이유:** 원격 좌석은 `ActionSeq` 가 직전 이하이면 거부한다. 새로 접속한 앱은 1부터 다시 세므로 재연결 순간 기준을 0 으로 되돌려야 한다.

## 5. 클라이언트

- **기기 식별자:** 첫 실행 때 GUID 생성·저장, 모든 접속에 첨부.
- **차례 카운트다운:** 내 프롬프트에 남은 초 표시(`SecondsLeft` 를 받은 시각부터 줄여 셈).
- **자리 비움 배너:** 내 좌석이 `Away` 면 하단에 "자리 비움 — AI가 대신 두는 중 [돌아가기]" → `Resume` 전송.
- **AI 대행 배지:** 다른 좌석이 `Away` 면 좌석 이름 옆에 "AI 대행".
- **자동 재접속:** 연결이 끊기면(서버가 `MatchEnded` 후 정상 종료한 경우 제외) 메뉴로 튕기지 않고 "재접속 중…" 오버레이 → 1s·2s·4s·8s… 간격(최대 8s)으로 약 2분간 재시도. 성공하면 `Lobby`+스냅샷으로 테이블 상태를 갈아끼우고 이어서 진행. 실패하면 지금처럼 메뉴로 돌아가며 안내.
- **앱 재실행:** "온라인 대전" → 같은 `id` 로 접속 → 서버가 진행 중인 판으로 돌려보냄(위 §4). 별도 화면 없음.
- **스냅샷 적용:** `TableViewModel` 이 매치 누적 점수를 `Lobby` 의 값으로 덮어쓰고, 진행 중 라운드 상태는 `StateUpdate` 로 그린다. 놓친 라운드 결과 팝업·플레이 로그는 복원하지 않는다.

## 6. 오류 처리 · 동시성

| 상황 | 처리 |
|---|---|
| 차례 대기 중 그 사람이 끊김 | 방이 좌석을 자리 비움으로 바꾸고 대기를 깨운다 → 30초를 기다리지 않고 대리 AI 가 즉시 둔다. |
| 재연결과 판 진행이 겹침 | 링크 교체·순번 초기화·스냅샷 송신을 방 잠금 하나 안에서. 세션 스레드의 방송도 같은 경로(링크 조회)를 거치므로 스냅샷 뒤 갱신 순서가 뒤바뀌지 않는다. |
| 대리 AI 결정 중 사람이 복귀 | 진행 중 결정은 그대로 적용(되돌리지 않음). 복귀는 다음 질문부터. |
| 사람 0명 대기 중 재접속 | 대기를 깨워 그 질문을 사람에게 묻는다(30초 새로 시작). |
| 사람 0명 2분 경과 | 세션 정지·방 닫기·`RoomClosed`. `id → 방` 항목 제거. |
| 레이트리밋·크기·형식·좌석 사칭 | 연결 계층에서 그대로. `Resume` 도 레이트리밋 대상. |
| 서버 로그 | 좌석 자리 비움/복귀, 시간 초과(대리 AI 결정), 재연결(좌석·연결 #), 중복 접속 교체, 사람 0명 멈춤·2분 종료. |

## 7. 테스트

- **원격 좌석 단위**(시간 제한을 짧게 주입):
  - 시간 초과 → 그 한 수만 대리 AI, 연속 2번 → 자리 비움, 자리 비움 → 즉시 대리 AI.
  - 아무 유효 액션 / `Resume` → 사람 있음 복귀.
  - 늦은 답 거부: `AskId` 불일치(차례·용 양도), 라운드 내 이미 결정된 큰 티츄·교환.
  - 대기 중 자리 비움 전환 → 즉시 깨어 대리 AI.
  - 순번 초기화 후 1번부터 받음.
  - 기존 `RemoteAgentTests`·AI·오라클 테스트 회귀 없음(순수 AI 경로 불변).
- **방**(가짜 시계·가짜 링크): 같은 `id` 재연결 → 같은 좌석·`Lobby`+누적 점수·스냅샷·순번 초기화; 중복 접속 → 옛 링크 닫힘; 사람 0명 → 멈춤, 2분 뒤 종료, 그 전 복귀 시 재개.
- **매치메이커:** `id → 방` 라우팅(재연결이 대기열을 건너뜀), 대기열 중복 `id` 교체.
- **E2E**(실제 WebSocket): 한 클라이언트가 판 도중 끊김 → AI 로 계속 → 같은 `id` 재접속 → 같은 좌석에서 끝까지 / 한 명이 영영 안 돌아와도 다른 사람은 완주 / 가만히 있는 클라이언트 → 시간 초과 → 자리 비움 / v2 접속 → 업데이트 안내.
- **클라이언트(Unity EditMode):** 재접속 재시도 로직(순수 클래스, 가짜 전송·시계), 카운트다운 문구, 자리 비움 배너 상태, 스냅샷의 누적 점수 반영(홀수 좌석 뒤집기 포함).
- **음성 대조:** `AskId` 검사, 순번 초기화, 대기 중 끊김 깨우기, 사람 0명 멈춤을 하나씩 빼면 해당 테스트만 실패.
- `Tichu.Net` 변경은 Unity 미러에 복사, 바뀐 core 테스트도 미러.

## 8. 완료 조건(DoD)

1. 위 테스트 + 기존 dotnet core·server·Unity Presentation·미러(클래스 필터) 회귀 없음.
2. **실기**(에디터 + S23, LAN 서버):
   - 판 도중 폰 비행기 모드 → AI 가 대신 둠 → 해제 → 같은 자리로 자동 복귀.
   - 앱 완전 종료 → 재실행 → "온라인 대전" → 진행 중인 판으로 복귀.
   - 2번 연속 시간 초과 → 자리 비움 배너 → [돌아가기].
   - 다른 기기에 "AI 대행" 배지.
   - 둘 다 나가면 2분 뒤 서버 로그에 방 종료.
3. 새 APK 로 확인. v2 앱은 업데이트 안내.
