## 2. 범위

### 2.1 앱 정체성 바꾸기
- `ProjectSettings/ProjectSettings.asset`: `productName: 용과 봉황`, `applicationIdentifier.Android: com.kas328.dragonphoenix`.
- 서명 키(`~/.keys/tichumaster-upload.jks`, 별칭 `tichumaster`)·환경변수 `TICHU_KEYSTORE_*` 는 **그대로** — 사용자에게 보이지 않고 패키지와 무관.
- 빌드 산출물 파일명(`TichuMaster-dev-arm64.apk`, `TichuMaster-{ver}-{code}.aab`)은 **그대로** — 내부 이름, 바꾸면 과거 문서·스크립트 경로만 깨진다.
- 게임 안 "티츄 선언"·"라지 티츄"·"스몰 티츄" 등 **규칙 용어는 그대로**.
- `README.md` 제목만 새 이름으로(공개 저장소 첫 줄이 스토어와 달라 보이지 않게). 본문의 "티츄" 규칙 설명은 그대로. 과거 보고서·스펙·계획 문서는 기록이라 손대지 않는다.
- Unity 에서 `productName` 이 한글이어도 Android 빌드가 되는지는 AAB 재빌드로 확인한다(2.6).

### 2.2 아이콘·피처 그래픽
- 원본: `docs/store/src/` 에 HTML(인라인 SVG) 한 장씩. 기존 `Assets/_Project/Art/Cards/Icons/Dragon.svg`·`Phoenix.svg` 그림을 그대로 끌어 쓴다(새 그림체 없음, 공식 아트 미사용).
- 렌더링: Edge 헤드리스 `--screenshot --window-size=W,H` → PNG. 다시 뽑을 수 있게 명령을 `docs/store/src/README.md` 에 남긴다.
- 산출물:
  - `docs/store/icon-512.png` — 512×512, 정사각 꽉 채움(Play 가 모서리를 깎는다), 펠트 배경 + 살짝 기운 용 카드.
  - `docs/store/feature-1024x500.png` — 1024×500, **투명 채널 없음**(Play 규격). 펠트 배경, 용·봉황 카드 두 장, 제목 "용과 봉황", 부제 "팀 카드게임". 글꼴은 설치된 Malgun Gothic.
  - 런처 아이콘 원본: `Assets/_Project/Art/AppIcon/` 에 적응형 배경(펠트 432×432)·전경(용 카드, 가운데 안전 영역 안, 투명 배경 432×432)·일반 아이콘(432×432, 둥근 사각 안쪽 여백) PNG.
- Unity 적용: PlayerSettings 의 Android 아이콘 — Adaptive(배경·전경), Round, Legacy 에 위 PNG 를 넣는다. 에디터 코드(`execute_code` 또는 1회성 에디터 메뉴)로 `PlayerSettings.SetPlatformIcons` 를 호출하고, 결과가 `ProjectSettings.asset` 에 직렬화됐는지 diff 로 확인한다.

### 2.3 스크린샷 (1920×1080, 4~6장)
- 후보 장면(우선순위 순):
  1. 한창 진행 중인 판 — 내 패와 테이블 위 카드
  2. 내 차례 패 고르기 — 선택된 카드가 올라간 상태
  3. 폭탄 또는 티츄 선언 순간(글로우·배지)
  4. 라운드 결과·점수
  5. 메인 메뉴 → 난이도 선택
  6. 온라인 대전 대기 화면
- 방법: 에디터 Game 뷰 1920×1080 고정, Play 모드에서 장면을 만든 뒤 MCP 스크린샷. 우연이 필요한 장면(폭탄)은 시드를 바꿔 찾고, 일정 시도 안에 안 나오면 티츄 선언 장면으로 대신한다. 디버그용 FPS 오버레이 등 개발 표시는 캡처에 나오지 않게 한다.
- 산출물: `docs/store/screens/01-*.png` …
- 캡션 문구를 이미지에 덧씌우지 않는다(원본 화면 그대로 — 실제 게임과 다른 인상 방지, 작업량 최소).

### 2.4 등록정보 문구 (한국어)
- `docs/store/listing.html` — 항목별 복사 버튼 없이 항목마다 블록 하나, 글자 수 표기.
  - 제목: "용과 봉황: 팀 카드게임"
  - 짧은 설명(≤80자): 2:2 팀 카드게임·AI/친구와 대전의 핵심 한 줄.
  - 자세한 설명(≤4000자): 게임 소개(4인 2:2 트릭테이킹, **"티츄(Tichu) 규칙으로 즐기는"**), 특징(AI 난이도 4단계·온라인 친구방·폭탄/용/봉황 등 특수 카드), 면책 문구 **"본 앱은 Tichu 의 저작권자·상표권자 및 공식 라이선스 앱과 관련이 없는 독립 제작물입니다."**
- 과장·검증 안 된 주장 금지("최강 AI" 등 측정 없는 표현 X). 기능 서술은 실제 구현된 것만.

### 2.5 개인정보처리방침 페이지 이름
- `gh-pages` 의 `privacy/index.html` 에서 "Tichu Master" 4곳을 새 이름으로(한국어 "용과 봉황", 영어 "Dragon & Phoenix" — 영어 단락이 이미 있으므로 영어 이름이 필요). 본문 내용(수집 없음 선언)은 **바꾸지 않는다** — 멀티플레이 반영 재신고는 M2b 에서.
- 절차: gh-pages 를 별도 worktree 로 열어 그 파일만 수정·`git add privacy/index.html`(**`git add -A` 금지**), 외부 리소스 0건 유지. **gh-pages 푸시는 사용자 승인 후**. 브랜치 삭제·이름 변경 금지.

### 2.6 검증
- 이미지: 크기·투명 채널 유무를 스크립트(Windows PowerShell 5.1 의 System.Drawing)로 확인. 피처 그래픽에 알파가 있으면 24비트로 다시 저장.
- 문구: 제목 ≤30, 짧은 설명 ≤80, 자세한 설명 ≤4000 자 — 스크립트로 셈.
- 정체성: Release AAB 재빌드(`Tichu/Build Release AAB`) → bundletool 로 매니페스트를 뽑아 `package="com.kas328.dragonphoenix"`, 라벨, 아이콘 리소스(`mipmap-anydpi-v26` 적응형) 존재 확인. versionCode 는 2 유지(새 패키지의 첫 업로드).
- 기존 자동 테스트: 코드 변경이 거의 없으므로 Presentation EditMode 클래스 필터 회귀 1회.
- 실기 대기 목록에 추가: 홈 화면 아이콘·이름 표시(잘림 여부), 적응형 아이콘 모양(원·물방울 등 런처별).

## 3. 하지 않는 것
- 게임 안 규칙 용어 변경, 게임 안 타이틀 화면 추가
- 영어 등록정보
- Data safety·개인정보처리방침 내용 재신고(M2b)
- 빌드 산출물 파일명·키스토어 이름 변경
- 홍보 영상(선택 항목)
- Play Console 입력·업로드 자체(사용자가 함)

## 4. 위험
- **패키지 ID 전제가 틀린 경우**(이미 업로드됨): 바꾸면 새 앱이 된다. → 구현 첫 단계 재확인.
- **한글 `productName`**: Android 라벨은 유니코드 문제없음이 일반적이나, 일부 빌드 경로(Gradle 프로젝트 이름)에 쓰이면 실패할 수 있다. → AAB 재빌드가 게이트, 실패 시 productName 을 영문으로 두고 Android 라벨만 리소스로 지정하는 대안.
- **에디터 캡처가 폰과 다르게 보임**(세이프 에어리어·해상도): 1920×1080 은 기준 해상도(CanvasScaler)와 같아 배치는 같다. 폰 노치 영역 차이는 스크린샷에 영향 없음.
- **상표 위험 잔존**: 설명문 표기도 권리자가 문제 삼을 여지는 0 이 아니다(조사 보고서에 기록). 사용자 수용.
